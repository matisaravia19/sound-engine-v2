# Internal Architecture

## 1. Proposed Crate Layout

```text
sound-engine/
  src/
    api/
    core/
    scene/
    simulation/
      tracing/
      diffraction/
      transmission/
      accumulation/
    acoustics/
      ir/
      filters/
    auralization/
      convolution/
      spatial/
    gpu/
      backend/
      rt/
      memory/
      sync/
      shader/
```

Detailed type/method specs for each module are in `docs/modules/`.

## 2. Module Responsibilities

- `api`: user-facing engine objects and thread-safe handles.
- `core`: orchestration, scheduling, state versions, mode management.
- `scene`: CPU-side scene graph, mesh/material assets, diff tracking.
- `simulation`: GPU dispatch logic and acoustic path sampling.
- `acoustics`: path-to-IR conversion, smoothing, normalization, band models.
- `auralization`: real-time DSP and output spatialization.
- `gpu`: Vulkan and memory abstractions used by simulation and DSP backends.

## 3. Data Ownership Model

Primary rule: each layer owns its native representation.

- `scene` owns canonical CPU geometry/material state.
- `simulation` owns GPU-ready scene mirrors (AS, compact buffers).
- `acoustics` owns rolling IR histories and smoothing state.
- `auralization` owns active convolution partitions and overlap buffers.

Data crosses layers through immutable snapshots or double-buffered handles.

## 4. State Versioning

Maintain monotonic version counters:

- `scene_version`
- `gpu_scene_version`
- `ir_version`
- `audio_ir_version_consumed`

This allows:

- quick stale-state checks,
- deterministic logs for thesis experiments,
- safe hot-swaps during runtime.

## 5. Threading Model

Threads:

- Control thread(s): API calls.
- Simulation worker: scene upload + GPU simulation + IR publish.
- Audio callback thread: consume IR snapshot + convolve.

Communication:

- MPSC queue for control updates.
- Lock-free ring or atomic pointer swap for IR snapshots.

## 6. Scheduler

Simulation tick stages:

1. Drain update queue.
2. Build scene diff plan.
3. Update GPU resources (batched).
4. Run simulation pipelines.
5. Build/publish new IR snapshot.

Skip policy:

- If simulation overruns, next tick can drop intermediate states but must keep latest authoritative state.

## 7. Scene-to-GPU Bridge

Bridge component: `simulation::scene_bridge`.

Responsibilities:

- Transform CPU mesh/material data into tightly packed GPU structs.
- Maintain indirection tables (`mesh_id -> blas_handle`, `material_id -> material_slot`).
- Apply partial updates when possible.

Simplification for thesis scope:

- No mesh-instance layer.
- Geometry and material mappings are direct.

## 8. Diffraction Extension Point

`simulation::diffraction` consumes a shared edge/corner dataset generated by scene preprocessing.

Contract:

- Input: edge candidates + visibility/context info.
- Output: additional arrival events into the same accumulator used by reflection paths.
- Toggleable at runtime by feature flag.

## 9. IR Cache Component

`acoustics::ir_cache` is a small internal module:

- Keyed by quantized source/listener positions.
- Invalidated by scene version bump.
- Returns closest reusable IR when movement is below threshold.
- Supports optional crossfade when replacing cache entries.

## 10. Testability Strategy

Unit tests:

- Geometry packing and scene diffing.
- IR binning/normalization math.
- IR cache hit/miss and invalidation behavior.
- Partitioned convolution correctness vs. CPU reference.

Integration tests:

- Deterministic synthetic scene snapshots.
- Regression tests on IR shape and energy decay.

Benchmark suite:

- Rays/sec and update latency.
- Audio CPU usage and callback overrun count.
- GPU memory usage per scene size.
